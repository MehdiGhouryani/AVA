# `packages/ava_ui_assets` — بستهٔ دارایی‌های UI

این پوشه در snapshot فعلی عمدتاً تصاویر و رجیستری صفحه‌محور آن‌ها را نگه می‌دارد؛ package مستقل و قابل اجرای Flutter نیست. اپ Flutter، بک‌اند و پنل ادمین هنوز در این snapshot پیاده‌سازی نشده‌اند.

## ساختار فعال

```text
packages/ava_ui_assets/
├── assets/
│   ├── characters/       تصاویر واقعی فعلی (Ava, Roka, Fandogh)
│   ├── icons/ui/         آیکون‌های رابط کاربری SVG/PNG
│   ├── illustrations/    تصویرسازی‌ها و اشیای محیطی
│   └── review/           candidateها، alternateها و اسکرین‌شات‌ها
├── preview/              تصویر/انیمیشن پیش‌نمایش
├── legacy/character_pipeline/  کد/metadata قدیمی، فقط بایگانی؛ اجرا نشود
└── manifest.json         رجیستری صفحه‌محور دارایی‌های فعلی
```

## مرزهای مهم

- `manifest.json` در ریشهٔ این بسته، رجیستری صفحه‌محور فعلی است. آن را با manifest قدیمی شخصیت‌ها یکی نگیرید.
- `legacy/character_pipeline/` شامل مدل Dart و ابزارهایی است که مسیرهای `ava/body/` و `friends/<id>/` را انتظار دارند. این مسیرها با assets فعلی تطابق ندارند؛ آن‌ها را اجرا/وارد برنامه نکنید تا قرارداد جدید تأیید و مهاجرت شود.
- `assets/characters/` فعلی شامل فایل‌های Ava و پوشه‌های Roka/Fandogh است. وجود تصویر به‌تنهایی به معنی تأیید نقش شخصیت یا اجازهٔ استفاده در صفحهٔ تولیدی نیست.
- `assets/review/` محل مرور است، نه دارایی تأییدشدهٔ محصول. فایل‌های `manifest.json` و تصاویر را قبل از انتشار با هم اعتبارسنجی کنید؛ هفت ارجاع به asset مفقود در manifest فعلی گزارش شده است.
- اسکرین‌شات کامل در UI محصول رندر نشود. candidateها را تا تخصیص صفحه و تأیید هنری در بخش review نگه دارید.

## پیش از مصرف در اپ

در فاز مربوطه، schema رجیستری و مسیرهای Flutter باید بر اساس دارایی‌های واقعی، نام‌گذاری نهایی شخصیت‌ها و منبع تصویری تأییدشده تعیین شوند. از اسکریپت‌های legacy برای ساخت manifest جاری استفاده نکنید.
