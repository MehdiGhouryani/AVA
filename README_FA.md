# AVA — راهنمای صاحب پروژه (فارسی)

این مخزن شامل مشخصات، داده‌های پایه، دارایی‌ها، prototype تجربهٔ کاربری و دستورالعمل‌های مرحله‌ای AVA است. **در snapshot فعلی هنوز اپ Flutter، بک‌اند و پنل ادمین قابل اجرا وجود ندارند.**

## هر جلسه چه کنی

1. آخرین ZIP کامل پروژه را در چت جدید پیوست کن.
2. این پیام ثابت را بفرست: «این zip پروژهٔ AVA است. ابتدا `AI_START_HERE.md`، `docs/PROJECT_STRUCTURE_FA.md` و `ai/phases/README.md` را بخوان؛ فایل‌های موجود را از برنامه‌های آینده تشخیص بده و طبق درخواست فعلی ادامه بده.»
3. در پایان، نسخهٔ ZIP به‌روز، گزارش کوتاه فارسی، فایل‌های تغییریافته و تست‌هایی را که واقعاً اجرا شده‌اند دریافت کن.

## راهنمای ابزار بر اساس مرحله

- مستندات و داده‌ها: مدلی با قابلیت خواندن/نوشتن فایل و اجرای کد.
- اپ Flutter: پس از ایجاد واقعی پروژه در `apps/mobile/`، از Flutter SDK و ابزار توسعهٔ محلی استفاده کن؛ فعلاً این مسیر فقط README راهنما دارد.
- پنل و API: `apps/admin/` و `services/api/` نیز در این snapshot فقط placeholder هستند.
- تصاویر: ابزار تصویری؛ خروجی‌ها تا زمان تأیید در بخش candidates/review نگه داشته شوند.
- صدا: مسیر تولید و بازبینی صوت هنوز بخشی از فازهای آینده است؛ وجود دستورالعمل آن به معنی آماده بودن سرویس نیست.

## فایل‌های مرجع و وضعیت فعلی

- `AI_START_HERE.md` قوانین شروع کار هوش مصنوعی و مرز فایل‌های موجود/غایب را مشخص می‌کند.
- `ai/phases/README.md` ترتیب فازها و محدودیت‌های پرامپت‌های فاز را بیان می‌کند. پرامپت‌ها برنامهٔ کارند، نه سند تأییدشدهٔ وضعیت اجرا.
- `docs/PROJECT_STRUCTURE_FA.md` نقشهٔ ساختار فعلی است؛ `docs/maintenance/PROJECT_FILE_TREE_FA.txt` درخت فایل‌های همین بسته است.
- `data/screens_v18.json` رجیستری منبع prototype فعلی و `data/state_contracts_v18.json` قراردادهای state نسخهٔ baseline هستند. این داده‌ها هنوز فاز P0 را برای تطبیق با تصمیم‌های نهایی طی نکرده‌اند؛ به‌ویژه گزینه‌های قدیمی ورود با ایمیل نباید به محصول منتقل شوند.
- `data/baseline/` منبع محتوای پایه است. تا وقتی task مشخصی نسخهٔ جدید ایجاد نکرده، منبع اولیه را مستقیم ویرایش نکن.
- `docs/spec_sources_v1_8/` اسناد تاریخی‌اند. مسیرهایی مثل `canonical/` و `prototype_source/` داخل آن‌ها متعلق به بستهٔ قدیمی‌اند، نه ساختار فعلی. این فایل‌ها را حذف/بازنویسی نکن؛ خروجی فعلی را در مسیرهای جدید بساز و تفاوت‌ها را ثبت کن.
- `docs/pedagogy/01_master_educational_spec_v2.md` و `02_stage_content_design_guide_fa_v2.md` دو سند آموزشی موجودند. فایل‌های `03…14_*` خروجی‌های برنامه‌ریزی‌شدهٔ فاز P0 هستند و هنوز وجود ندارند.
- `packages/ava_ui_assets/` بستهٔ منابع تصویری است؛ `manifest.json` ریشه رجیستری صفحه‌محور فعلی است. خط لولهٔ قدیمی Dart/شخصیت به `packages/ava_ui_assets/legacy/character_pipeline/` منتقل شده و نباید اجرا یا import شود؛ مسیرها/schema آن با دارایی‌های فعلی فرق دارد. موارد `assets/review/` تأییدشده برای محصول نیستند.

## فایل‌ها و ورودی‌های آینده

در این snapshot فایل‌های `ai/STATE.md`، `ai/DECISIONS.md`، `ai/PROTOCOL.md`، `ai/OPEN_QUESTIONS.md`، `ai/FILE_MAP.md`، `inputs/INDEX.md` و پوشه‌های `inputs/` و `design/` موجود نیستند. ارجاع پرامپت‌ها به آن‌ها را به معنی وجودشان تلقی نکن. پوشه یا فایل جدید فقط هنگامی ساخته شود که task مربوط به آن رسیده باشد؛ هر فایل ارسالی صاحب پروژه باید همراه با مسیر، منشأ و هدف آن ثبت شود.

## قاعدهٔ طلایی

قبل از حذف یا جایگزینی فایل، وابستگی‌هایش را جست‌وجو کن. اسناد تاریخی نسخه‌دار، داده‌های baseline و فایل‌های generated را فقط با تصمیم/فرایند مشخص تغییر بده. اگر یک تصمیم فقط در پرامپت قدیمی آمده و منبع تأییدش موجود نیست، آن را «تأییدنشده» علامت بزن؛ از خودت تصمیم قفل‌شده نساز.
