# موجودی صوت AVA — قرارداد متصل به content v3 در ۰٫۶٫۱

منبع ماشین‌خوان این گزارش `design/audio.inventory.json` است و `scripts/validate-audio-inventory.py` آن را با شناسه‌های واقعی `content.fa.json` تطبیق می‌دهد. این موجودی فایل صوتی تولید نمی‌کند و به معنی تأیید تلفظ نیست.

## پوشش فعلی

| گروه | تعداد | الزام انتشار |
|---|---:|---|
| prompt فعالیت‌های شنیداری/آگاهی واجی | ۷ | فایل انسانی approved در انتشار نهایی |
| صدای کمکی فعالیت‌های تشخیص | ۵ | اختیاری؛ متن همیشه دیده می‌شود |
| روایت صفحه‌های قصه | ۹ | اختیاری؛ متن کامل fallback است |
| بازخورد غیرگفتاری | ۱ | اختیاری و قابل حذف |

در مجموع ۲۲ نیاز صوتی ثبت شده است. سه مورد تازه واژه‌های محرک «بابا»، «مادر» و «آب» برای صدای آغاز/پایان‌اند. موارد حرف/صدا با وضعیت `needs_educator_script` نگه داشته شده‌اند، چون پیش از ضبط باید روشن شود منظور نام نشانه، واج، یا تلفظ در بافت است. از یک فایل برای این نیت‌های متفاوت بدون بازبینی آموزشی استفاده نمی‌شود.

## قواعد ثابت

- شناسه صوت مستقل از نام فایل و URL است.
- اپ در این فاز همچنان TTS فارسی آفلاین را به‌عنوان fallback اختیاری استفاده می‌کند.
- هیچ فعالیتی فقط با صوت قابل تکمیل نیست؛ hint یا متن دیداری باقی می‌ماند.
- master، delivery key و checksum تا زمان وجود فایل واقعی `null` می‌مانند.
- صوت لازم فعالیت شنیداری تا وضعیت `approved` اجازه ورود به release تولیدی ندارد.
- `audioRef`های content v3 مستقیماً با همین inventory تطبیق داده می‌شوند؛ فایل، گوینده، license/consent، QC و transcode در CMS فاز ۰٫۷٫۰ اضافه می‌شوند.

## دستور کنترل

```sh
python3 scripts/validate-audio-inventory.py
```
