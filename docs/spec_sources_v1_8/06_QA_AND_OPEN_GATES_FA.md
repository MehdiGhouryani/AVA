# ۰۶: کیفیت، آزمون‌ها و گیت‌های باز

## چه چیزی واقعاً آزموده شد
آزمون‌های مرورگر، load بدون خطای browser/network، رندر ۵۸ رکورد پایه، ۳۵۹ انتخاب state، هندسهٔ ۴۸ رکورد غیرCMS در سه عرض، CMS در دسکتاپ و سناریوهای تعاملی را بررسی می‌کنند. مجموع هندسهٔ default = ۴۸×۳ + ۱۰ = ۱۵۴ بررسی؛ هر بررسی عرض، آزمون native viewport با ارتفاع مستقل نیست.

رسیدهای JSON از اجرا ایجاد می‌شوند. هر عدد آخرین اجرای واقعی معتبر است؛ این سند replace نتیجهٔ تست نمی‌شود. خروجی‌های screenshot و board بصری قبلی در پاکسازی ۴–۷ حذف شده‌اند؛ receiptهای رندر قبلی دیگر مرجع وضعیت جاری نیستند. تعدادی surface در حالت‌های مختلف یکسان‌اند ولی cue/pose/state متفاوت دارند؛ به این‌ها «صفحهٔ مستقل جدید» نمی‌گوییم.

اندازهٔ تمام controlهای اندازه‌گیری‌شدهٔ طرح پایه با حداقل child=۶۴ و parent/CMS=۴۸ کنترل می‌شود. CTA کودک ۷۲ است. سلکتور state، دفتر طراحی و modalها سطح جدا هستند؛ آزمون کامل modal و font scaling/native باقی است.

تعامل‌های آزموده: سه صحنهٔ معرفی، رضایت موبایل نمایشی، انتخاب اشتباه و cue آرام، مکث/بازگشت، ذخیرهٔ avatar پروفایل دوم، استقلال avatar پروفایل اول، commit و idempotency پاداش نمونه، بازبینی CMS با دلیل، دفتر طراحی ۳۹۰px، reduced-motion و visual quiet cue.

## بازبینی مستقل
گزارش مستقل، ایرادهای نمونه را در برابر اپ تولیدی مشخص کرده است. route catalog و ورود اولیهٔ S06-B، bypass **دفتر طراحی** هستند و مجوز runtime production نیستند. گزارش در `qa/independent_review_fa.md` و رسید پاسخ در `qa/QA_DISPOSITION_FA.md` آمده‌اند. حذف duplicate CMS، رضایت تمام auth روش‌ها، profile-scoped state، ذخیرهٔ ناموفق، cleanup timer و عدم نمره‌دهی stroke آزاد در اصلاح نهایی انجام شده‌اند.

## چیزی که آزمون رندر اثبات نمی‌کند
درک کودک، صحت phonics فارسی، کیفیت صدا، ترتیب stroke، درست‌بودن distractor، اثربخشی آموزش، TalkBack واقعی، pixel-perfect native، امنیت auth/backend، درخواست حذف واقعی، دانلود/hash/signature یا verified purchase با screenshot اثبات نمی‌شوند.

## پروتکل pilot
سن ۴ تا ۷، بدون خواندن دستور توسط آزمونگر، با روایت اختیاری و بدون وعدهٔ جایزهٔ مالی. رفتارهای قابل مشاهده: یافتن شروع، فهم cue، کشف replay، recovery بعد دو تلاش، تشخیص همراه شخصی، بازگشت بعد مکث، فهم parent handoff توسط سرپرست و راحتی sensory.

آزمونگر باید خطا را از کودک جدا کند: آیا دستور مبهم بود، هدف کوچک بود، صدا نامفهوم بود یا مفهوم هنوز آموزش داده نشده؟ stopping rule برای ناراحتی/خستگی و رضایت برای ذخیرهٔ مشاهدات از پیش مشخص شود. نتیجهٔ pilot به اصلاح design/learning contract بازگردد، نه توجیه layout موجود.

## محدودیت پژوهش دولینگو
منابع عمومی رسمی، guideline و مقاله‌ها خوانده شدند. همهٔ UI جاری اپ لاگین‌شده یا rolloutهای Android/iOS مشاهده نشدند. قیاس مستند است، اما ادعای «ممیزی کامل نسخهٔ فعلی اپ دولینگو» نداریم. مرجع public App Store ABC ممکن است قدیمی باشد؛ تاریخ و محدودیت در گزارش پژوهش ثبت شده‌اند.
